# Входные данные каталога EKT

## Источник и границы проверки

Документ описывает **наблюдаемую структуру одного сохранённого ответа списка товаров**, а не гарантированную схему всего API EKT и не публичный Product-контракт приложения.

- Образец: `catalog-service/local-evidence/products-page-1.json` (локальный файл, игнорируется Git).
- Дата анализа: 2026-09-23. Время получения ответа в файле не записано.
- Размер выборки: 20 товаров, 20 уникальных ID.
- SHA-256 образца: `02818ee6061019012c42ef6e355835ff890b0675e4b7b1d7b458e657c42a1a54`.
- По назначению CLI и имени файла образец соответствует `GET https://ekt.kz/api/products?page=1`; внутри JSON указано `page: 1`.
- HTTP status, заголовки, использованные credentials и факт выполнения Basic Auth по одному JSON-файлу не устанавливаются. Авторизованный запрос в текущем процессе не повторялся.

Подключение и остальные проверки принадлежат [Issue #2](https://github.com/BAITC-Hacks/hack-e4fbf0e4-dairn/issues/2). Общий журнал исследования: [api-findings.md](../catalog-service/docs/api-findings.md). Публичный API приложения описан отдельно в [API.md](API.md).

## Обёртка списка

Корневой JSON — объект с четырьмя полями:

| JSON path | Наблюдаемый тип | Значение | Интерпретация и ограничения |
| --- | --- | --- | --- |
| `$.page` | number, целое | `1` | Номер страницы в ответе. Начало нумерации и поведение других страниц ещё не проверены. |
| `$.per_page` | number, целое | `20` | Заявленный размер страницы; в образце совпадает с длиной `items`. Возможность его настройки неизвестна. |
| `$.count` | number, целое | `20` | Совпадает с длиной `items`. Не установлено, это размер текущей выборки или другое значение; не считать общим количеством товаров каталога. |
| `$.items` | array of object | 20 элементов | Массив записей товаров. |

Полей общего количества страниц, следующей страницы или курсора в этом образце нет. Нельзя вычислять полноту каталога по `count: 20` или считать, что получены все товары EKT.

## Запись товара

Все восемь полей ниже присутствуют во всех 20 записях. Это наблюдение выборки, а не доказательство обязательности полей для любых ответов API.

| JSON path | Наблюдаемый JSON-тип | Заполнение | Содержание |
| --- | --- | --- | --- |
| `$.items[].id` | number, целое | 20/20, без null | Числовой идентификатор записи; пример `45357`. Уникален в этой странице. Стабильность между запросами ещё не проверена. |
| `$.items[].article` | string | 20/20, без null | Значение артикула; встречаются кириллица и специальные символы: `ярп4520`, `310100080_`. Уникальность и возможность поиска по нему не установлены. |
| `$.items[].name` | string | 20/20, без null | Название товара с исходной пунктуацией и техническими обозначениями. |
| `$.items[].price` | number | 20/20, без null | Числовая цена. В этой выборке значения целые, от `53` до `76940`. Валюта, НДС, единица продажи и смысл вида цены не указаны. |
| `$.items[].image` | string или null | 19 строк, 1 null | Ссылка на изображение либо отсутствующее значение. У товара `25397` значение null. Доступность ссылок не проверена. |
| `$.items[].url` | string | 20/20, без null | Ссылка на страницу товара на сайте. Доступность и стабильность URL не проверены. |
| `$.items[].url_api_detail` | string | 20/20, без null | Ссылка на API деталей товара; пример `https://ekt.kz/api/products/detail?id=45357`. Наличие ссылки не подтверждает успешный ответ endpoint. |
| `$.items[].offers` | array | 20 пустых массивов | Во всей выборке `[]`. Тип элементов и семантика непустого массива неизвестны. |

`id` и `article` — разные поля. Например, товар с `id: 25397` имеет `article: "310100080_"`. Подменять один идентификатор другим нельзя.

## Пример из ответа

Ниже одна реальная запись из сохранённой страницы; изменено только форматирование JSON. Это не полный ответ и не синтетический Product DTO.

```json
{
  "id": 45357,
  "name": "***LED STARK 30W 2400Lm d98x180 4000K IP20 MEGALIGHT (20)",
  "article": "ярп4520",
  "price": 1810,
  "image": "https://ekt.kz/upload/iblock/c39/u58k0kbv7koy4uikpznyywf0i5h1my7e/led_stark_30w_2400lm_d98x180_4000k_ip20_megalight_20.jpg",
  "url": "https://ekt.kz/catalog/spets_predlozhenie/aktsiya_megalight_polnyy_sklad_polnyy_bak/_led_stark_30w_2400lm_d98x180_4000k_ip20_megalight_20/",
  "url_api_detail": "https://ekt.kz/api/products/detail?id=45357",
  "offers": []

```

## Чего образец не подтверждает

В записях списка нет отдельных полей категории, бренда/производителя, валюты, наличия, складов, количества, структурированных характеристик, сертификатов, описания или времени обновления товара. Это **отсутствие в обследованном ответе списка**, а не утверждение об отсутствии этих данных в деталях или во всём API.

Пустой `offers` не означает нулевой остаток или отсутствие товара: содержимое и назначение этого массива ещё не установлены. Число в `price` не доказывает возможность покупки или актуальность цены на момент следующего обращения.

Название может содержать мощность, размеры, цветовую температуру, IP-класс и похожее на название бренда слово. Эти фрагменты не являются отдельными проверенными характеристиками. Аналогично путь в `url` нельзя автоматически считать авторитетной моделью категорий.

## Рекомендации к обработке в #2

Это предлагаемые правила адаптера по результатам выборки; нормализатор ещё не реализован и окончательный Product зависит также от исследования деталей.

| Исходные данные | Правило для будущей нормализации |
| --- | --- |
| `id` | Проверять целочисленный формат без потери точности. Во внутреннем контракте допустима непрозрачная строка, сохраняющая идентичность исходного ID. Не подменять артикулом. |
| `article` | Сохранять строку без удаления кириллицы, подчёркиваний и возможных ведущих нулей. Возможное имя в Product — `sku`; соответствие закрепить в mapping. |
| `name` | Сохранять исходное значение. Поисковую обработку текста выполнять отдельно от фактов каталога. |
| `price` | Разбирать точным десятичным типом, например `BigDecimal`; не ограничивать целыми числами по этой выборке. Не назначать валюту без подтверждения. Пропуск не превращать в 0. |
| `image` | При null сохранять отсутствие изображения. Не добавлять фиктивную ссылку. |
| `url` | Проверять формат ссылки до её использования. Не извлекать неподтверждённые факты из пути. |
| `url_api_detail` | Оставить внутри интеграции. Для запросов использовать известный endpoint и кодировать `id`; не отправлять Basic Auth на произвольный URL из ответа. |
| `offers` | До изучения непустых значений не задавать придуманную структуру элемента и не выводить из массива наличие/остаток. |

Дополнительные поля будущих ответов требуют анализа; пропуски и ошибки типов должны обрабатываться явно. Raw JSON не должен становиться контрактом для HTTP-потребителей или ИИ. Неизвестное наличие отличается от подтверждённого отсутствия, неизвестная цена — от нуля.

Для будущего поиска подтверждены текстовые входы `article` и `name`. Поддержка поиска на стороне EKT не проверена. Для надёжного подбора аналогов этой страницы недостаточно: нет подтверждённых структурированных параметров совместимости и наличия. Сходство названий не доказывает взаимозаменяемость.

## Следующие проверки

1. Получить страницу 2 и повтор страницы 1; сравнить ID, состав страниц и метаданные. Выяснить смысл `count` и критерий окончания пагинации.
2. Получить детали нескольких товаров из списка, например `45357` и `25397`, и описать их схему отдельно от списка.
3. Проверить валюту, единицу продажи, наличие/склады, характеристики и сертификаты по деталям; если значения отсутствуют или неоднозначны, зафиксировать это.
4. При обнаружении непустого `offers` описать элементы массива и их связь с товаром.
5. Зафиксировать HTTP status и время получения новых образцов, отдельно проверить безопасные ошибки API. Ошибку локальной конфигурации не считать ответом EKT.

Команды из корня проекта после сборки дистрибутива:

```sh
bash catalog-service/bin/ekt-cli list --page 2 --output catalog-service/local-evidence/products-page-2.json
bash catalog-service/bin/ekt-cli detail --id 45357 --output catalog-service/local-evidence/product-45357.json
bash catalog-service/bin/ekt-cli detail --id 25397 --output catalog-service/local-evidence/product-25397.json
```

Логин и скрытый пароль запрашиваются локально. Credentials, Authorization и их Base64-представление не включаются в документацию. Raw-файлы остаются в игнорируемом каталоге; перед публикацией новых примеров необходимо проверить их содержимое.
