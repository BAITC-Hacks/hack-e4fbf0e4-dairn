# Catalog API

Единый публичный контракт Issues #3 и #4. Наблюдаемая исходная схема и происхождение
образца: [EKT_DATA.md](EKT_DATA.md). Исследование: [api-findings.md](../catalog-service/docs/api-findings.md).

Дополнительный сценарий разбора пользовательского текста и предложения кандидатов:
`POST /api/catalog/assist/search`, [контракт и запуск](AI_SEARCH.md). Он не изменяет каталог
и не заменяет проверку взаимозаменяемости в GET endpoint аналогов.

## Текущая возможность

Сервис использует общий нормализатор и Product из слоя интеграции. Он возвращает данные
**первой страницы списка**: это краткая карточка, не ответ непроверенного detail endpoint.
Категория, бренд, сертификаты и характеристики не выводятся из названия/URL.
Наличие неизвестно, валюта неизвестна. Подбор аналогов на таких данных невозможен.

## Запуск на полученном JSON

Из корня проекта, JDK 21 и Gradle 8.8:

```sh
CATALOG_SOURCE=snapshot \
CATALOG_SNAPSHOT_PATH=catalog-service/local-evidence/products-page-1.json \
gradle :catalog-service:runServer
```

В другом терминале:

```sh
curl -i 'http://127.0.0.1:8080/api/catalog/products/45357'
curl -i 'http://127.0.0.1:8080/api/catalog/products?query=310100080_'
curl -i 'http://127.0.0.1:8080/api/catalog/products/25397/availability'
curl -i 'http://127.0.0.1:8080/api/catalog/products/45357/analogs'
```

Для живого чтения: `CATALOG_SOURCE=live` и переменные EKT в окружении процесса согласно
README. Это отдельный явный режим, он не подменяется snapshot при сбое. Сам факт наличия
live-клиента не подтверждает выполненную живую проверку. По умолчанию `CATALOG_SOURCE=disabled`.
Неверная конфигурация выбранного источника останавливает запуск с безопасной ошибкой.

Адрес по умолчанию `127.0.0.1:8080`; настройки `CATALOG_HOST`, `CATALOG_PORT`.
`run` по-прежнему запускает CLI; сервер запускается задачей `runServer`.
Файл .env автоматически не загружается.

## Маршруты

| GET | Успешный ответ / ограничение |
| --- | --- |
| `/api/catalog/products/{id}` | 200: `{product, metadata}`, карточка из загруженной выборки |
| `/api/catalog/products?query={query}` | 200: `{items: [...], metadata}` |
| `/api/catalog/products/{id}/availability` | 200: `{productId, availability, metadata}`; сейчас UNKNOWN |
| `/api/catalog/products/{id}/analogs` | 422: недостаточно данных для известного товара |

`id` — непрозрачная строка длиной 1–256 символов без пробельных/управляющих символов.
Числовой EKT id преобразуется в десятичную строку без потери точности. `article`
отображается в `sku` с сохранением кириллицы, подчёркиваний и ведущих нулей.
Артикул не является ID: для него используется `query`.

`query` — ровно один параметр, после trim 1–200 символов, без управляющих символов.
Поиск подстроки в sku и name без учёта регистра (Locale.ROOT); точное совпадение SKU
идёт первым, остальные сохраняют порядок источника. Никакого внешнего search endpoint нет.

## Product и пропуски

| Поле | Значение |
| --- | --- |
| id | Строка исходного числового id |
| sku | Исходный article или null |
| name | Исходное название; отсутствие/неверный тип — ошибка источника |
| price | `{amount: "1810", currency: null}` либо null |
| images | Массив проверенных по формату HTTP(S) ссылок; отсутствующее image → [] |
| pageUrl | Исходный url либо null; credentials внутри URL запрещены |
| availability | `{status: "UNKNOWN", quantity: null}` для изученной схемы |

amount — точная десятичная **строка**, чтобы браузер не потерял разряды.
Отсутствие price не превращается в 0, currency не назначается автоматически.
Пустой или непустой offers не интерпретируется как наличие/количество.
Модель допускает AVAILABLE / UNAVAILABLE / UNKNOWN, но наблюдаемая схема
позволяет только UNKNOWN. Нельзя использовать её для подтверждения корзины.
url_api_detail и raw JSON не выходят в публичный контракт.

## Полнота и актуальность

Каждый успешный ответ содержит metadata:

```json
{
  "source": "EKT_PRODUCT_LIST",
  "mode": "SNAPSHOT",
  "coverage": "PARTIAL",
  "pages": [1],
  "loadedProducts": 20,
  "totalProducts": null,
  "observedAt": null,
  "loadedAt": "2026-09-23T10:00:00Z",
  "expiresAt": null,
  "freshness": "UNKNOWN",
  "detailLevel": "LIST_SUMMARY"
}
```

loadedAt в примере условный — реальное время загрузки устанавливает сервис.
Для snapshot время получения исходных данных неизвестно: mtime файла не используется
как время наблюдения. Повторное чтение файла не делает его коммерческие данные актуальными.
Для live: observedAt — время получения ответа, expiresAt — окончание TTL кеша,
freshness=RECENTLY_FETCHED. Это не обещание, что поставщик обновил цену/остаток именно тогда.

Всегда coverage=PARTIAL, даже при пустой/короткой странице: смысл count и конец пагинации
ещё не установлены. totalProducts=null. Отсутствие результата не доказывает отсутствие товара у EKT.

## Ограничения поиска и кеша

| Параметр | Значение |
| --- | --- |
| Страницы / upstream-запросы за загрузку | Только page=1; максимум один запрос, без повторов |
| CATALOG_MAX_PRODUCTS | 100 по умолчанию, 1–1000; нормализуется только префикс страницы |
| Размер тела источника | До 8 MiB (и для snapshot) |
| CATALOG_LOAD_TIMEOUT_MS | 35000 по умолчанию, 1–120000 |
| CATALOG_CACHE_TTL_SECONDS | 60 по умолчанию, 1–3600 |
| CATALOG_SNAPSHOT_PATH | Обязателен только при CATALOG_SOURCE=snapshot |

Загрузка лениво при первом запросе. Детали, поиск и наличие используют одну выборку.
После TTL следующий запрос обновляет её; одновременные успешные загрузки объединяются mutex.
До TTL повторных запросов к источнику нет. После ошибки обновления старые данные
не выдаются как успешный ответ; запрос получает явную ошибку, последующий может повторить
загрузку. Фонового обхода страниц, базы, векторного поиска и полного скачивания каталога нет.

## Ошибки

Все ответы JSON с Cache-Control: no-store. Формат:

```json
{"error":{"code":"PRODUCT_NOT_IN_LOADED_SAMPLE","message":"Product is not in the loaded sample; existence in the full catalog is unknown"}}
```

| HTTP | code | Смысл |
| --- | --- | --- |
| 400 | INVALID_PRODUCT_ID | Некорректный id |
| 400 | INVALID_SEARCH_QUERY | Некорректный/повторённый query |
| 404 | PRODUCT_NOT_IN_LOADED_SAMPLE | ID нет в ограниченной выборке; существование в EKT неизвестно |
| 404 | PRODUCT_NOT_FOUND | Зарезервировано для подтверждённого отсутствия, сейчас не выдаётся |
| 404 | ROUTE_NOT_FOUND | Нет маршрута |
| 405 | METHOD_NOT_ALLOWED | Неподдерживаемый метод |
| 503 | CATALOG_NOT_READY | Источник выключен |
| 503 | UPSTREAM_UNAVAILABLE | Ошибка чтения/сети/авторизации/таймаута источника |
| 502 | UPSTREAM_INVALID_RESPONSE | Неверная схема, JSON, типы, дубли ID или превышение размера |
| 422 | ANALOGS_INSUFFICIENT_DATA | Нет проверенных характеристик и наличия для аналогов |
| 501 | ANALOGS_NOT_IMPLEMENTED | Подбор не реализован (при выключенном каталоге) |
| 503 | ANALOGS_UNAVAILABLE | Зарезервировано для будущего подбора |
| 500 | INTERNAL_ERROR | Непредвиденная ошибка без текста исключения |

404 от upstream **списка** не считается подтверждением отсутствия конкретного товара:
он отображается как UPSTREAM_UNAVAILABLE. Ошибки не превращаются в пустой успешный каталог.
Отмена coroutine пробрасывается.
